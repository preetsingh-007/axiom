# Axiom demo video

| File | What |
|---|---|
| [`out/axiom-demo.mp4`](out/axiom-demo.mp4) | 16:9, 1080p, ~2:50. A pitch of eight features, then a set-up guide against a stopwatch. |
| [`out/axiom-teaser-vertical.mp4`](out/axiom-teaser-vertical.mp4) | 9:16, 1080×1920, ~60 s. Cold open, three features, end card. |
| `out/*.srt` | Captions for both. |

Everything is generated by code in this folder and can be rebuilt with `GEMINI_KEY=… bash video/make.sh`.

## How it is made

| Piece | Source | Notes |
|---|---|---|
| Script and voice | `narration.json`, `tts.py` | Two voices from [Kokoro](https://huggingface.co/hexgrad/Kokoro-82M), an open-weights TTS model that runs offline: `af_heart` (F) and `am_michael` (M). |
| Timing | `timeline.mjs` | Every scene is a whole number of bars at 110 BPM, so cuts land on the beat. The music, mix, captions and frames all read `build/timeline.json`. |
| Music and sound | `audio.py` | Original, synthesised in NumPy, with no samples and no licensing. A minor, i–VI–III–VII. Risers into each title, a breakdown for the bridge and a chime for each checklist step. The music ducks about 9 dB under the voice. |
| App footage | `record-footage.mjs` | The real app, built and driven by Playwright (see below). |
| Demo papers | `assets/papers.mjs` | Fictional papers, typeset with KaTeX and printed to PDF by Chromium, so they have a real text layer. |
| Handwriting | `handwriting.mjs` | A tiny stroke font, used to scribble on the whiteboard for the AI to read. |
| Frames | `compositor/` | One HTML page that renders frame *t* deterministically through `window.seek(t)`. |
| Encoding | `render.mjs` | Screenshots every frame and encodes H.264 with ffmpeg. The soundtrack is normalised to −14 LUFS. |

### What is real and what is illustrated

The app footage is the actual app:
- AI answers are live Gemini calls (`gemini-flash-lite-latest`): handwriting and equation OCR, suggested tags, cloze cards, and the Settings **Test** button.
- Device linking goes through the real relay (`server/relay.mjs`).
- Git backup runs the app's real sync code, against an in-memory stand-in for the GitHub API (`github-sim.mjs`), so recording never touches a real account.
- The repository view in feature 7 is drawn from the files that sync code actually pushed.

Screens outside the app are labelled **Illustration** in the video:
- the terminal
- the browser install prompt and the iPad share sheet
- the Git host's token page
- AI Studio's key page

The stopwatch shows a typical first-time setup time, not a measurement. The npm install is visibly fast-forwarded (×6).

### Footage capture

Chrome's screencast only delivers 1× frames, so clips are captured as Playwright screenshots at 1.5× (1920×1140). That runs at about 14 fps. To compensate, every clip is performed 2.5× slower than real time: scripted pauses, pointer paths, typing and CSS animations. The compositor plays it back at ×2.5, which gives smooth 30 fps footage at real-time speed. Each `build/clips/<clip>/index.json` lists the frames with timestamps and named marks (for example `lasso1` or `flash`). The compositor uses the marks to time-map footage onto scenes.

## Rebuilding pieces

```bash
bash video/make.sh assets voice audio   # voice lines, timeline, music + mix
bash video/make.sh record               # re-record app footage (builds the app, starts preview + relay)
bash video/make.sh render               # frames → mp4
node video/render.mjs --stills 14,90    # quick PNG checks in video/build/stills/
```

To edit the words, change `narration.json`, then run `voice`, `audio` and `render`. Scene lengths follow the narration.
